# DEVIN RUN 7 指示書 — summary_ja の全件拡充

あなたは Devin CLI (SWE-2) として、このワークスペースで作業する自律実装担当です。
Run 1〜6 の報告 (reports/devin-run1〜6/REPORT.md) をまず読んでください。
既存の検収済みテスト (117件) を壊さないことが前提です。

## 目的

ユーザー要望「各項目の概要説明をもっと充実させてほしい (しっかりめに)」に応え、
data/vendor/ の全31カタログ・2,073件の `summary_ja` を、検索結果一覧で
「受けるかどうか」を判断できる水準まで書き直す。

## 書き直しの基準

- **分量**: 2〜3文、80〜180字を目安 (日本語)。1文だけの現行 summary_ja は
  原則として拡充対象
- **含める要素** (元データにある範囲で): 何を学べるか / 対象者・前提 /
  ハンズオン・ラボ等の実習要素の有無 / 形式 (コース、ラーニングパス、認定 等)
- **材料は元データだけ**: title、description、services、domain、level、
  duration_text、type の範囲で書く。元データに無い具体的内容 (レッスン名、
  章立て、製品機能の詳細、前提知識の推測) は**絶対に書かない** (捏造禁止)
- description フィールドは出典として改変しない。書き直すのは summary_ja のみ
- 既に基準を満たす summary_ja (2〜3文で要素が揃っているもの) は無理に
  書き直さず、軽微な整形に留める。その件数をカタログ別に REPORT に書く
- 文体: です・ます調ではなく体言止め・常体の簡潔な説明文 (既存 summary_ja の
  文体に合わせる)。誇張・宣伝文句は書かない
- 日本語の推敲: yomiyasu スキルが利用可能なら最終チェックに使う。
  使えない場合はその旨を REPORT に書いたうえで、自身で丁寧に推敲する

## 進め方 (重要)

- カタログ単位で1ファイルずつ処理し、終わるごとに
  `reports/devin-run7/REPORT.md` の進捗表を更新する (中断しても再開できる形)
- 処理順は件数の多い順ではなく、既存 summary_ja が特に薄いカタログから
  (充足状況は自分で実測して決め、根拠を REPORT に書く)
- 全カタログ完了後に ETL を再生成する (build/unified.json、catalog.db、
  web/unified-compact.json)。link_lang など既存フィールドを壊さないこと

## 機械チェック (テスト追加)

- 全件の summary_ja が 40字以上 (拡充後の下限として妥当な値に調整可。
  根拠を REPORT に書く)
- タイトルが異なるレコード間で summary_ja の完全一致が無いこと
  (定型文のコピペ検出)
- summary_ja に URL やマークダウン記法が混入していないこと

## 成果物

- 書き直した data/vendor/*.json (summary_ja のみ変更) と ETL 再生成物
- 追加テスト (既存117件 + 新規が全て通ること)

  変更前後の文字数分布、材料不足で拡充が限定的だったカタログと理由、
  既知の制限を正直に書く
