# DEVIN RUN 3 指示書 — 改善パッケージ I1〜I4

あなたは Devin CLI (SWE-2) として、このワークスペースで作業する自律実装担当です。
計画の正本は docs/PLAN.md、Run 1/2 の報告は reports/devin-run1/REPORT.md と
reports/devin-run2/REPORT.md です。まず全部読んでください。
既存の検収済みモジュールとテスト (42件) を壊さないことが前提です。

## I1 導線100%化 (Google の none 22件)

- 現状 link kind=none は Google Skills の22件のみ (元データに URL が無い)
- Google Skills の公式検索/カタログ URL 形式を、元データ内に実在する URL や
  公式ページの実在パターンから確認できた場合に限り、kind=search の導線を追加する
- 確認できない場合は捏造せず none のままにし、REPORT に「何を根拠に判断したか」
  を正直に書くこと (この判断自体が成果物)
- plan オーバーレイ側で none になるケースにも同じ扱いを適用する

## I2 検索精度

- 短クエリ (3文字未満) の LIKE フォールバックのノイズ除去: 現状 "AI" が
  "Available" にマッチする。単語境界を意識したマッチ (タイトル/要約/サービス内の
  独立した単語として現れる場合を優先) に改善し、ノイズが消えたことをテストで示す
- 検索モード追加: OR 検索とフレーズ検索を API と CLI の両方で使えるようにする
  (既定は現行の AND のまま)
- ゴールデンクエリを拡充: 現在の4件 (Fargate / MCP / PostgreSQL / Kubernetes)
  に加え、実データで検証可能なものを 15件程度まで増やす (例: AI, Terraform は
  データに無ければ不可。セキュリティ、エージェント、Lambda、VPC、データベース等、
  実在する語で選ぶこと)。各クエリの期待条件をテストに明記する

## I3 推薦の最適化

- 現在のスコア順貪欲パックを、所要時間判明レコードについてはナップサックDP
  (空き時間内でスコア合計を最大化) に置き換える
- 決定論 (同入力→同結果) と、各候補への「選ばれた理由」付与は維持する
- duration 不明レコードの扱い (末尾追加+明示) は現行仕様を維持する
- テスト: 貪欲では最適にならない入力例で DP がより高いスコア合計を選ぶことを示す。
  既存の推薦テスト (時間上限・決定性・理由) も引き続き通ること

## I4 正規化の残件

- AWS の plan_month 複合値 (例 "2027-03 データ基盤 / 分析") を
  plan_month ("2027-03") と plan_theme ("データ基盤 / 分析") に分割する。
  Azure / Google / plan で既に分離している形式に合わせる
- Azure の level 複数値 (例 "intermediate;advanced") を levels リストとして
  保持し、level 絞り込みが各要素にマッチするようにする (既存 level フィールドの
  互換は保つ)
- 分割できない形式の値は推測で壊さず、そのまま保持して REPORT に件数を書く
